Entity Reference

USER (core_user)

Registered users with email auth, budget settings, and optional encrypted Gemini API key. Uses UUID primary key (user_id).

STORE (core_store)

Retailers recognized on receipts. Physical store or Online ecommerce channel.

CATEGORY (core_category)

Spending categories (Groceries, Transport, Fast Food, etc.) with essential vs non-essential flag. 12 seeded by default.

RECEIPT (core_receipt)

Captured till slip per purchase. Linked to owning user and store. Stores slip identity (branch, cashier, slip #) for returns.

RECEIPT_ITEM (core_receiptitem)

Individual line items on a receipt. Linked to parent receipt and spending category. Impulse-purchase flag per item.

LOYALTY_POINTS (core_loyaltypoints)

Store loyalty points (e.g. Smart Shopper, ClubCard) extracted from receipts, with optional expiry date and voucher label.

BUDGET_ALERT (core_budgetalert)

Deduplication ledger for automated budget and points-expiry notifications (50%/80%/100% budget, 7-day/1-day points).

LOGIN_CODE (core_logincode)

Short-lived 6-digit OTP for passwordless email/SMS/WhatsApp login. Single-use, 10-min expiry, last-5 pruned per email.

LOGIN_AUDIT (core_loginaudit)

Per-successful-signin audit trail across every channel: password, email/SMS/WhatsApp code, Apple, Guest. Includes IP + UA.

Relationship Summary

  • USER → RECEIPT: 1-to-Many. A user owns many receipts; a receipt belongs to one user (CASCADE delete).
  • STORE → RECEIPT: 1-to-Many. A store appears on many receipts; deleting a store is PROTECTED if receipts exist.
  • RECEIPT → RECEIPT_ITEM: 1-to-Many. A receipt has many line items; deleting a receipt removes all items.
  • CATEGORY → RECEIPT_ITEM: 1-to-Many. A category classifies many line items; deletion is PROTECTED.
  • USER → LOYALTY_POINTS: 1-to-Many. Users accumulate points per store. (CASCADE on user delete).
  • STORE → LOYALTY_POINTS: 1-to-Many. Store issues the points (PROTECTED).
  • RECEIPT → LOYALTY_POINTS: 1-to-Many (optional). Points optionally linked to the source receipt they were extracted from (SET NULL).
  • USER → BUDGET_ALERT: 1-to-Many. Deduplication ledger per user/period/kind (UniqueConstraint).
  • USER → LOGIN_AUDIT: 1-to-Many. Full sign-in history per user (CASCADE).
  • USER → LOGIN_CODE: Logical (no FK — codes are transient email-keyed before account lookup).
